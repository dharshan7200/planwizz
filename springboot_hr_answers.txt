PlanWizz — Spring Boot Technical HR Question Set Answers
====================================================================

1. Project Introduction
--------------------------------------------------------------------
Tell me about your PlanWizz project.
PlanWizz is a full-stack timetable generation application. It takes raw university enrollment data in PDF format, parses the courses and available timings, and uses a Constraint Satisfaction algorithm to generate a clash-free schedule based on a student's preferences.

What problem does PlanWizz solve?
Students often spend hours manually cross-checking course slots to create a valid timetable without time clashes. PlanWizz automates this tedious process, ensuring 100% accuracy and saving time.

Why did you choose this problem?
Because I experienced the frustration firsthand during course registration. I wanted to build a practical tool that solved a real problem for myself and my peers.

Who uses the application?
University students who need to plan their academic schedules before or during course registration.

What is the complete workflow?
1. The user uploads a PDF of available courses and selects preferences (like "no classes on Friday").
2. The React frontend sends this data to the Spring Boot backend.
3. The backend parses the PDF using regex to extract course slots.
4. The CSP (Constraint Satisfaction Problem) algorithm finds a clash-free schedule.
5. The JSON schedule is returned to the frontend, which renders it on a calendar.

What technologies did you use?
Frontend: React, Vite, Tailwind CSS.
Backend: Java, Spring Boot 3, REST APIs.
Deployment: Render (Docker for backend, static hosting for frontend).

Why did you choose Spring Boot for the backend?
Spring Boot is robust, scalable, and provides enterprise-level performance. Since the timetable algorithm is CPU-intensive, Java's multithreading and strong typing made it the perfect choice. It also offers excellent built-in REST and file-handling capabilities.

What was your exact contribution?
(Assuming full-stack role): I designed the system architecture, built the Spring Boot backend including the PDF parser and CSP algorithm, developed the React frontend, and managed the deployment using Docker and Render.

Which Spring Boot modules did you personally develop?
I developed the REST controllers for file uploads, the service layer for PDF extraction and algorithm logic, and configured global exception handling.

What was the most difficult backend problem you faced?
Writing a robust PDF parser using regex that could handle slight variations in formatting without crashing. Also, optimizing the backtracking algorithm to run quickly even when constraints were tight.

How did you solve it?
For the algorithm, I used the Minimum Remaining Values (MRV) heuristic, which drastically reduced the search time by failing fast when a schedule path was impossible.

What makes your application different from a normal timetable application?
It automatically extracts data from PDFs rather than requiring manual data entry, and it guarantees a zero-clash schedule by treating the scheduling as a mathematical Constraint Satisfaction Problem.

How did you test the application?
I tested it manually with complex real-world student PDFs, wrote unit tests for the PDF parsing regex to ensure data was extracted correctly, and tested the REST endpoints using Postman.

How did you deploy it?
I dockerized the Spring Boot application and deployed it to Render as a web service. The React frontend was also deployed to Render as a static site.

If you had one more month, what would you improve?
I would add caching (like Redis) so that if 10 students upload the same PDF with the same constraints, the algorithm doesn't re-calculate it. I would also add user authentication to save timetables to a database.


2. Spring Boot Architecture
--------------------------------------------------------------------
Why did you choose Spring Boot?
It eliminates boilerplate configuration, has a massive ecosystem, provides an embedded server (Tomcat), and is the industry standard for Java backends.

What is Spring Boot?
It is an extension of the Spring framework that makes it easy to create stand-alone, production-grade Spring-based applications with minimal configuration ("opinionated defaults").

What is the difference between Spring and Spring Boot?
Spring is a large framework requiring a lot of manual XML or Java configuration. Spring Boot sits on top of Spring, provides auto-configuration, and includes embedded servers so you can just "run" the app.

What is the role of @SpringBootApplication?
It is a combination of @Configuration, @EnableAutoConfiguration, and @ComponentScan. It marks the main class and tells Spring to start scanning for components and configuring the app.

Explain the architecture of your Spring Boot application.
It follows a standard layered architecture: Controller (handles HTTP requests) -> Service (handles business logic/algorithms) -> Repository (handles database operations, if any).

Why did you use Controller → Service → Repository?
Separation of concerns. Controllers shouldn't know how to generate timetables; they just handle HTTP. Services shouldn't write SQL. This makes the code testable, maintainable, and readable.

What is the responsibility of each layer?
- Controller: Receives HTTP requests, validates input, calls Service, returns HTTP responses.
- Service: Contains core business logic (e.g., PDF parsing, CSP algorithm).
- Repository: Interacts with the database (e.g., saving generated timetables).

Why shouldn't we put business logic directly inside the controller?
If you do, the controller becomes massive, hard to test, and impossible to reuse. If you wanted to call the timetable generator from a scheduled background job, you wouldn't be able to easily if the logic is stuck inside an HTTP controller.

What happens when a request reaches your Spring Boot application?
Tomcat receives it -> DispatcherServlet routes it -> Controller handles it -> Service processes it -> Controller returns a ResponseEntity -> DispatcherServlet converts it to JSON and sends it back.

What is dependency injection?
It is a design pattern where an object receives its dependencies from an external source (the Spring IoC container) rather than creating them itself using the 'new' keyword.

What is IoC?
Inversion of Control. Instead of your code controlling the creation of objects, you give control to the Spring framework to create and inject them.

How does Spring perform dependency injection?
By using annotations like @Autowired, and by managing a "Context" of beans.

What is a Spring Bean?
An object that is instantiated, assembled, and managed by the Spring IoC container.

What is @Component?
A generic annotation to mark a Java class as a bean so Spring will manage it.

What is @Service?
A specialization of @Component used to mark classes that hold business logic.

What is @Repository?
A specialization of @Component used for database access classes. It also translates database exceptions into Spring exceptions.

What is @RestController?
A combination of @Controller and @ResponseBody. It tells Spring that this class handles REST API requests and that all return values should be converted to JSON automatically.

Constructor injection vs field injection — which would you use and why?
Constructor injection. It allows making fields 'final' (immutable), makes it easier to write unit tests without Spring, and ensures the class cannot be instantiated without its dependencies.


3. REST API Questions
--------------------------------------------------------------------
What is REST?
Representational State Transfer. It is an architectural style for designing APIs that use standard HTTP methods (GET, POST, PUT, DELETE) and exchange data (usually JSON).

Why did you use REST APIs?
Because it is the standard, easiest way for a React frontend to communicate with a Java backend over the web.

Explain your /api/generate API.
It is a POST endpoint. It accepts a MultipartFile (the PDF) and a JSON string (user constraints). The controller passes these to the TimetableService, which extracts data and runs the algorithm, returning a List of course schedules. The controller returns this list as JSON with a 200 OK status.

Why did you use POST?
Because we are uploading a file and submitting data to create a new resource (a timetable). 

When would you use GET instead?
To fetch data without modifying the server state, e.g., fetching a saved timetable.

What is the difference between PUT and PATCH?
PUT replaces an entire resource. PATCH partially updates a resource.

What do 400, 401, 403, 404 and 500 mean?
400: Bad Request (invalid input).
401: Unauthorized (not logged in).
403: Forbidden (logged in, but lack permissions).
404: Not Found.
500: Internal Server Error (backend crashed).

How do you validate request data?
By using Spring Boot Validation (e.g., @Valid, @NotNull) in the controller.

How do you handle API exceptions?
Using a global @ControllerAdvice to catch exceptions and return a structured JSON error response.


4. Spring Dependency Injection
--------------------------------------------------------------------
Who manages the objects in Spring?
The Spring IoC Container (ApplicationContext).

What is ApplicationContext?
The central interface for the Spring IoC container. It holds all the beans and manages their lifecycles.

What is @Autowired?
An annotation that tells Spring to automatically inject a dependency into a field, setter, or constructor.

Can Spring inject multiple implementations of the same interface?
Yes. If you have two implementations of `PdfParser`, Spring will throw an error unless you specify which one to use.

What are @Primary and @Qualifier?
@Primary marks a bean as the default choice. @Qualifier explicitly tells Spring which specific bean name to inject.

Interview trap: "If I remove @Service from your service class, what happens?"
The Spring container will not recognize it as a Bean. When the Controller tries to inject it, the application will crash on startup with a `NoSuchBeanDefinitionException`.


5. Database / Spring Data JPA
--------------------------------------------------------------------
What is JPA?
Java Persistence API. It is a specification/standard for ORM (Object Relational Mapping) in Java.

What is Hibernate?
Hibernate is the actual implementation of the JPA specification. It does the heavy lifting of converting Java objects into SQL queries.

What is Spring Data JPA?
An abstraction layer over JPA that makes it incredibly easy to write database queries by just declaring interfaces (like JpaRepository).

What does @Entity do?
Marks a Java class to be mapped to a database table.

What is JpaRepository?
An interface provided by Spring Data JPA that gives you standard CRUD (Create, Read, Update, Delete) methods out of the box without writing any SQL.

What is the N+1 query problem?
When an ORM executes 1 query to get a list of N parent entities, and then executes N additional queries to fetch their children. It causes severe performance issues. Solved by using `JOIN FETCH` in JPQL or entity graphs.

What is @Transactional?
It ensures that a method is executed within a database transaction. If an exception occurs, all database changes in that method are rolled back.


7. Exception Handling in Spring Boot
--------------------------------------------------------------------
How do you handle exceptions in your project?
I use a Global Exception Handler marked with @ControllerAdvice. 

What is @ControllerAdvice?
An annotation that allows you to handle exceptions across the whole application globally, intercepting errors before they reach the user.

How would you return a proper error response?
I created a custom `ErrorResponse` class containing `status`, `message`, and `timestamp`. The global handler catches an exception and returns a `ResponseEntity<ErrorResponse>`.


9. Spring Boot + React Integration
--------------------------------------------------------------------
How does React communicate with Spring Boot?
Using the `fetch` API or `Axios` to send HTTP requests to the Spring Boot REST endpoints.

What happens if the frontend sends invalid JSON?
Spring Boot will fail to deserialize it and throw an HttpMessageNotReadableException, which my global exception handler catches and turns into a 400 Bad Request response.

How did you handle CORS?
By adding a `@CrossOrigin` annotation on the controller or configuring a global `WebMvcConfigurer` to allow requests from the React app's domain.

Why does CORS occur?
Cross-Origin Resource Sharing. Browsers block frontend code from calling APIs on a different domain/port for security reasons, unless the backend explicitly allows it.


10. PDF Upload + Spring Boot
--------------------------------------------------------------------
How does React send the PDF to Spring Boot?
Using a `FormData` object in JavaScript and sending it as a `multipart/form-data` POST request.

What is MultipartFile?
A Spring interface that represents an uploaded file received in a multipart request.

How do you prevent malicious file uploads?
By checking the file extension, validating the MIME type, setting a strict file size limit, and never executing the file on the server.


12. Spring Boot + Algorithm Scenario
--------------------------------------------------------------------
"What if 1,000 students call it at the same time?"
Synchronous processing would crash the server. I would put the system behind a Load Balancer pointing to Multiple Spring Boot instances. I would introduce a Message Queue (RabbitMQ). The controller would immediately return a "Job ID" and put the request in the queue. Background workers would process the queue safely. Redis would cache duplicate requests.


16. Production / Real-World Questions
--------------------------------------------------------------------
Scenario: Someone sends an invalid request directly to your API without using React. Can they bypass your frontend validation?
Yes. Frontend validation is solely for user experience. Hackers can bypass it easily using Postman. Therefore, strict Backend validation (@Valid, custom checks) is absolutely mandatory for security and data integrity.

18. The Most Important Spring Boot Chain
--------------------------------------------------------------------
HTTP Request -> Tomcat intercepts the HTTP bytes.
DispatcherServlet -> Spring's front controller looks up the route mapping.
Controller -> Handles input, delegates work.
Service -> Performs the business logic.
Repository -> Spring Data JPA executes SQL.
Database -> Saves/Returns data.
Response -> Spring's Jackson library serializes Java objects back to JSON.
